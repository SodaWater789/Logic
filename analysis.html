Ratio test method

The time complexity is found by experiment. Each task is run on a formula with n nodes and then on a formula with 10n nodes. The time is measured both times and divided.

If the ratio is aboutThen the task is
10O(n) linear
100O(n2) quadratic
1000O(n3) cubic

For the truth table, one atom is added each time instead. If the time doubles each time then the table is O(2k).

The test formula is made by makeFormula(c) in task6.cpp. It has c clauses like (x1+(~x2)) joined with * and uses only 100 atoms, so only n changes between the two runs. Run it with menu option 3.

Machine used: Windows, MinGW g++ 6.3 with -O2. Times come from clock() which counts in milliseconds, so very small times of 1 or 2 ms are not exact.

The time doubles with each new atom so the truth table is exponential, O(2k).

At this speed 30 atoms would take about 1.5 hours. The smallest SAT 2002 file used below has 26 atoms and a much bigger tree, so its table would take about an hour. A file with 450 atoms has 2450 rows, more than the number of atoms in the universe. This is why the program prints the truth table only for formulas with at most 15 atoms.

What the results show

  • Output is correct for every file. For all eight files the recursive and iterative traversals gave the same output and both height functions gave the same height.
  • Real data is also linear. From 5col180_15_4 to k2fix_gr_rcs_w9 the nodes grow 14.8 times and Task 1 grows 15.1 times. From k2fix_gr_rcs_w9 to cache_10 the nodes grow 3.5 times and Task 1 grows 4.0 times.
  • The tree stays short. readCNF joins clauses as a balanced tree, so the height grows like log n. It goes from 11 to only 28 while the nodes grow from 441 to 5.5 million. This keeps the recursion depth small, so recursive functions never run out of stack.
  • Evaluation depends on the number of atoms. In cache_10 evaluation takes about 5 times longer than one traversal even though it visits the same nodes. It has 227210 atoms, so each map lookup takes about 18 steps, which is the log k part of O(n log k).
  • Task 1 is the slowest step because it works on all tokens including the brackets, which is about 2.2 tokens for each node, and it copies and reverses the token list twice.
  • The truth table is skipped for every file because even the smallest file has 26 atoms.

Memory

One Node holds a string and two pointers. With MinGW 32 bit this is 32 bytes and on a 64 bit compiler it is about 48 bytes.

The tree memory grows linearly with n. The token lists need about the same memory again. The stacks used by the iterative functions hold at most h nodes, except post order and level order height which can hold O(n). The truth table needs only O(k) extra memory because it builds one row at a time and does not store the table.
